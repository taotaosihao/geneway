## 1. Locked Boundaries：目标与范围

### 1.1 唯一建设目标

全新建设基于 DeepSeek Harness（DSH）原生运行与插件机制的 Geneway，使用户能把一项范围明确的工作交给稳定的数字员工；员工在允许的能力范围内取得真实事实，缺少条件时保留待补充事项，获得补充后继续，并交付可核查的结果。

首版必须同时完成：

| 目标 | 必须交付的行为 |
|---|---|
| G1 真实工作 | 普通业务入口中的员工调用至少一个已授权真实业务来源；结构化结果、自然语言说明与来源一致，并可追问。 |
| G2 持续负责 | 同一工作等待补充后可继续；刷新、正常重启不丢待办关联；明确确认的信息能跨工作使用、修改和删除，归属正确。 |
| G3 实例与能力独立 | 同一份插件支持两份连接及两名员工的差异绑定；第二个不同能力通过插件接入，不修改 AgentLoop、会话调度或恢复协议。 |

底座探针、一次真实查询、数字员工首版是不同完成节点。不得以插件注册成功或 G1 单独通过宣布首版完成。

首版使用范围是一个已授权的人类操作者管理多名数字员工、可信插件、只读业务接入。多名数字员工不代表多人私有会话或多租户隔离。

### 1.2 不继承、不增加

新系统不依赖旧 Geneway 的代码、运行服务、数据库、会话、令牌、插件协议或开发验收流程。不做旧系统兼容、迁移或修复，不将旧测试和演示作为新验收标准。不以保留文件为理由引入历史运行依赖，也不擅自删除旧目录。

不建立第二套 Agent 驱动器、插件安装与生命周期协议、Workflow DSL、固定专家委员会、通用记忆平台、复杂调度平台、插件市场或事务性热升级。不预设独立网关、Control Plane、Worker、队列或数据库服务。

协作、外部消息渠道、自动定时唤醒、共享知识、多个人类用户开放和业务写操作不自动包含在首版。小纬可作为统一入口，但不成为所有员工连接与信息的共同归属主体，也不建立永久主从关系。

## 2. Accepted Assumptions：采用的前提与未验证事实

以下是设计前提，不是已运行的事实：

- DSH 是选定执行底座，具体可安装包集、外部插件接口与 Client 接入方式在首个薄探针中核验；不得直接宣称上游文档中的接口已经在 Geneway 可用。
- 一个可信运行域、一个已授权操作者足以验证首版；普通业务入口仍不得拥有任意 Host 代码安装或底座配置修改权限。
- 同进程内可以处理普通超时、未配置和可捕获工具错误；不承诺任意插件死循环、进程退出或内存耗尽的强隔离。
- 首项业务为真实只读查询；数据权限、模型路由和允许发送的数据范围必须在实际使用前明确，不从旧项目搜取凭据或默认调用生产环境。

若前提不成立，只暂停受影响的实现或验收。可以继续无依赖的产品代码与受控测试，但不能降低真实工作标准或转而建设无关平台。

## 3. 首项真实工作与第二能力

### 3.1 首项任务

沿用 v3 的默认任务：操作者交给员工一个工单，员工根据真实状态、计划数量和已完成数量，形成有来源的生产进展说明。未给出可唯一识别的工单时，明确缺失条件并在需要稍后继续时保留待办。

业务工具的最小结果包含实际取得的工单标识、状态、计划数量、完成数量、单位、来源定位和本次查询时间；源更新时间或修订标识只有来源真实提供时才记录。源时间缺失必须说明，不以查询时间冒充源时间。

数量和单位先由业务函数校验与规范化。计划数量为正且数量口径一致时可计算完成占比；缺失值、零分母和口径冲突不补造百分比。完成占比不等于计划偏差；没有真实计划基线，不声称落后或提前。异常数量如实标明，不为美化结果静默截断或改值。

完整完成要求目标工单明确、必要读取成功、必需事实有效、结果和来源可定位。来源错误或必要事实缺失可以交付已知信息与明确未知项，但不能伪称完整任务成功。

首版不要求设备映射、Hive 报警或多系统联合查询。它们不是首项任务的隐藏前置。

### 3.2 真实接入边界

开始实现业务字段前确认一个已授权环境中的真实接口、认证方式、工单标识及数量/单位/时间含义。优先选择已有且满足权限和字段要求的 API，不兼容旧 Geneway 专用 Workflow 令牌，不伪造旧字段。

只有不合适的旧专用 API 可用时，将窄业务 API 建设作为独立集成任务，不自动改动 GearJob、Hive 或 Kivo。改选首项任务必须明确修订受影响的目标与验收，不得静默变为 mock 演示。

真实来源未准备好只阻塞相应接入与 G1 完成。受控服务可继续验证其他结构，但不能替代至少一个真实来源。

### 3.3 第二能力

采用一个无连接依赖的确定性节拍换算工具：输入可用时长（秒）与目标件数，输出完成该目标所需的允许平均节拍（秒/件）。输入必须有限且为正，单位必须明确；例如 3,600 秒、60 件对应 60 秒/件。

结果明确这是按输入推算的所需节拍，不是设备测得的实际周期或额定产能。不由模型自行计算数值，不引入第二个大型业务系统，不要求专用页面，也不为纯计算工具创建虚假连接实例。

此能力必须经原生插件装配、员工能力绑定、工具调用和通用结果展示进入产品，不能硬编码为聊天入口的特殊分支。

## 4. 产品模型、原生执行与插件的责任

### 4.1 最小对象与唯一主责

下表定义产品语义，不要求等量的数据表、服务或公共 SDK。

| 对象 | 稳定关联与必要内容 | 唯一写入主责 |
|---|---|---|
| 员工 | 独立员工标识；操作者归属、职责、模型引用、技能与能力绑定 | Geneway 产品配置 |
| 插件代码 | 原生插件标识、安装包与版本、工具贡献 | 受控部署装配 |
| 连接实例 | 独立连接标识；目标业务实例、插件类型、凭据引用、范围、启用状态 | Geneway 产品配置；凭据材料另由服务端秘密存储持有 |
| 能力绑定 | 员工与工具/技能/允许连接及动作的关系 | Geneway 产品配置 |
| 委托 | 仅在需要等待或继续时持久化：稳定工作标识、归属、目标、已明确对象、缺失条件、下一步、原生会话/执行/结果关联 | Geneway 产品应用层 |
| Session 与执行 | 使用所选 DSH 的实际标识、历史和运行记录 | DSH；Geneway 只写产品归属关联 |
| 已确认信息 | 稳定记录标识、内容、操作者与员工范围、明确确认依据、更新时间 | Geneway 产品信息入口 |

显示名、插件名、工具名不得替代员工或连接的稳定身份。一次执行只有一个确定的员工归属，以及零个或一个委托归属；即时问答不强制创建工作记录。一个委托可以关联多次执行。

首版原生 Session 不跨员工复用。切换员工必须选择或建立该员工自己的 Session，不能把所有员工上下文和工具权限合并到一个“小纬全局 Session”。

### 4.2 执行路径

产品入口接收用户输入，服务端解析已认证操作者、员工及必要的工作关联，以当前绑定装配 DSH 原生执行。建立产品关联后启动原生执行，取得原生标识后补全对应关系。

DSH 负责模型调用、工具调度、运行状态与原生历史。Geneway 不复制 token 流、工具步骤、重试程序或运行检查点。工作页面的运行中、取消、失败等执行信息来自原生引用或投影；产品只持有待补充、用户明确结束和结果关联等必要业务事实。

DSH idle、流结束、HTTP 200 均不等于业务完成。只有满足该任务结果条件、所需结果已持久化且关联可读取，才将工作呈现为完成。结果未结算或关联不完整时如实显示未完成/中断，不伪造成功。

### 4.3 插件边界

插件交付可复用代码能力，连接与员工是产品实例。一份插件可服务多份连接；新建员工或连接不复制插件代码、不新增部署单元。

产品功能先集中在一个产品插件中。业务插件可同时包含 HTTP 客户端、字段规范化、确定性函数、原生工具及可选展示。Skill 提供方法和表达要求，不发放权限，不代替业务计算。只有工具的插件必须能够使用通用结果展示。

使用原生注册、依赖与资源清理；不再包一层 Geneway install/activate/dispose。普通业务扩展主要修改自身插件、技能、绑定和必要产品接口，不改 AgentLoop 或会话调度。确有新产品概念时允许增加小接口，不以绝对零共享修改指标制造多层间接适配。

## 5. 绑定、权限与连接变化

实际调用处从受信执行上下文和产品记录解析员工、工作及连接。客户端或模型提交的连接标识仅是选择参数，不能作为授权；不接受模型任意提供的 URL 或凭据。

每次实际业务派发及新增重试都检查当前绑定、启用状态、动作范围和上游权限；这包括 DSH 或工具适配器内部发起的实际重试。无法经过该检查的自动重试路径应关闭或纳入同一受控调用入口，不另建通用重试调度器。UI 中的业务读取也不得绕过同一检查。DSH scope 用于能力组合和可见性，不单独承担业务授权。纯计算工具仍检查员工是否绑定了该能力。

不得用进程全局的“当前员工/当前连接”解决工具去向。同名工具在 A、B 员工交错调用时，各自保持受信身份、连接与结果归属。

新增绑定可在下一次执行装配时生效。撤销绑定或禁用连接生效后，后续实际派发不得使用旧授权；已通过派发边界的在途请求传播所支持的取消，并按真实结果说明，不承诺撤回远端已接收的请求。

将连接改指另一个业务实例时创建新连接标识；同一目标的凭据轮换可保留连接身份，后续派发解析当前有效凭据引用，不永久使用 Session 内缓存的旧凭据。等待中的工作保留原目标依据，原连接失效时不得自动换到另一实例中查询同名工单。需要换目标时必须由操作者明确选择并确认工作对象，记录该变化。

原生部署配置拥有插件装配；产品存储拥有员工、连接与绑定；运行中的工具集合只是投影。初始产品配置可以由维护者写入唯一受控存储，后续页面编辑写入同一处，不形成可独立修改的 YAML 与数据库竞争副本。

## 6. 连续性、信息撤销与历史

### 6.1 等待与继续

缺失工单标识时，员工说明缺什么；确需稍后继续的工作先保存必要待办，再向用户显示可继续入口。等待期间不保持模型运行、不轮询催办、不保存可执行步骤。

刷新或正常重启后，操作者能够重新找到同一工作标识并补充；服务端复核当前归属与授权，再启动一次关联的新执行。工单一旦明确，不因模糊指代静默换单。新会话中存在多个待办时必须明确选择，不按“最近一条”猜测。

继续可以复用经验证合适的原生 Session，也可使用新的 Session；连续性由目标、事实与关联保证，不依赖某个浏览器对象、WebSocket 或内存 Agent 持续存活。

### 6.2 确认信息

仅用户明确确认的信息进入跨工作记录，普通聊天和模型推断不自动升级为长期信息。默认范围为当前操作者与员工，不能自动共享给其他员工。

普通业务入口提供查看、修改与删除。下一项工作使用当前有效值；删除后不再由产品信息机制检索或注入旧值。继续旧工作时，实际执行上下文只装配必要目标事实、用户补充、必要业务观察与当前有效信息，并检查 DSH 对旧 Session 的自动继承。若不能在原 Session 中排除已删除或被替代的确认信息，则使用新 Session 承接同一工作标识，旧 Session 留作可读历史。不得通过旧摘要、隐藏提示或完整对话重新导入被撤销的有效记忆；这不是清除全部历史，也不修改 DSH 会话调度。

历史消息仍可以显示，不承诺撤回已经发送给模型的内容，也不把删除等同于清除所有历史。验收检查实际上下文装配和存储，不因模型偶然使用相同表达风格判定删除失败。用户后续主动重新提出同样要求，属于新的指令。

### 6.3 结果与恢复

当前业务事实以上游本次授权读取为准；当次观察、来源和时间随原生持久化工具结果保留。历史卡片不随最新查询被覆盖，最新查询形成新观察。业务判断由一个明确业务函数输出，模型和 UI 消费同一结果。

产品保存原生持久化结果引用与必要归属，不复制完整结果正文或整套运行日志。引用须在正常重启、约定的同版本卸载重挂及备份恢复后仍可解析，并能核对员工、委托、执行及所需来源依据；具体原生标识或恢复映射在探针中确定。

原本未完成的执行在恢复后如实显示中断；已有持久完成事实但结果丢失时显示“历史结果不可用/恢复不完整”，不得改写成当时从未完成，也不能宣称恢复验收通过。若原生结果已经结算，可在用户打开对应工作时读取并补全关联；否则由用户发起新的读取，不自动重放旧工具调用。

需要保留数据时，备份同时覆盖产品记录及其引用的原生历史。恢复后校验员工、工作、确认信息、结果关联可读；凭据引用不可解析时连接应不可用，不能因字符串存在就显示已恢复连接。

## 7. 普通业务入口与完整用户旅程

### 7.1 入口责任

拟实现的普通入口称“Geneway 工作台”，优先使用 DSH Client 与会话能力做产品化。具体 URL、端口、控件和启动命令当前尚未实现，属于 DEP-ENTRY；不得将本节当成现有可运行路径。

工作台至少可选员工、提交工作、查看工作反馈与来源、停止执行、找到待补充工作并继续。按增量增加确认信息查看/修改/删除，以及连接配置中的绑定、测试和禁用。不先做插件市场或完整管理后台。

后续验收中的补充、继续、信息修改删除、取消与连接禁用必须从普通产品入口完成，不能靠手改数据库、调试控制台或构造请求代替缺失 UI。服务端直调可以用于核查授权、数据和持久结果。

初始插件安装、模型路由与凭据由可信维护者配置，不暴露到业务入口。基于真实 HTTP 服务验证 HTML 和 JS/CSS；字符串渲染单测、合成页面或仅截图不能替代实际可操作界面。

### 7.2 必须完整驱动的旅程

| 旅程 | 合法前提与普通入口步骤 | 最终结果与回读 |
|---|---|---|
| J1 真实工作与追问 | 已授权操作者选择员工，使用已授权只读连接输入明确工单；查看进展说明并追问依据，再查询最新。 | 每次结果归属同一员工/目标，说明与实际字段、统一计算一致；旧观察可回读，新观察独立保存。 |
| J2 同一委托等待后继续 | 选择员工，提出缺工单标识的工作；看见待补充；刷新并正常重启；找到同一工作，补充标识并继续。 | 工作标识、员工与目标关联不丢；等待不调用模型；新执行使用当前授权并产出可定位结果。 |
| J3 确认信息可管理 | 明确确认一项格式偏好；在新工作中使用；查看、修改后再发起工作；删除后开启新工作，并检查一次既有待办的继续路径。 | 正确范围使用新值，其他员工不串用；删除值不被持久信息机制重新注入；历史展示保持历史含义。 |
| J4 两员工、两连接 | 一份插件配置 A/B 两员工及 X/Y 两连接；对相同业务编号交错读取；变更 A 绑定，禁用一个连接，构造未绑定连接的直接请求。 | 受控服务记录证明未串用；撤销后无新的受控越权派发；B 和不相关聊天/能力不受普通连接故障影响。 |
| J5 第二能力与生命周期 | 绑定节拍工具，输入明确数量与时长，查看通用结果；同 Host 内卸载重挂同版本插件，再调用。 | 无专用页面仍可用，无虚假连接实例；工具不重复、卸载后旧入口不可调用，自有资源正确清理。 |

J1 至少来自一个真实业务来源；J4 的两连接与边界失败可使用受控服务，不能因此省略 J1。使用同一候选、相同关联对象与数据模式完成各自旅程，不能拼接不同实现的局部结果冒充完整闭环。

## 8. 数据与实现选择

产品存储在薄探针中作一次有依据的选择：原生扩展存储若支持稳定记录、按归属读取、修改删除、正常重启、备份恢复，且数据寿命不依赖单个 Session 或插件挂载，就优先复用。仅能写临时 metadata 不算满足。

不满足时采用一个进程内的小型嵌入式产品存储，不新增数据库服务。具体库和表结构允许实施者根据选定运行环境选择；不得同时建立两个可写产品事实源，不为这两种选择建设通用存储平台。

产品配置、待办与确认信息由产品存储管理，原生运行和历史由 DSH 管理。不同存储之间不预建分布式事务、消息队列或补偿框架；通过先建立归属、保留原生结果引用、读取时核对与如实呈现中断控制当前需求。

确定性字段规范化、完成占比和节拍换算使用普通业务函数及测试。调用路径、UI 和解释不得各自实现竞争的公式。

## 9. 施工增量与路径边界

只有获得明确实施请求后进入本节。所有增量在独立新工程中实施，本轮不创建该工程。

|---|---|---|
| I1 一项真实委托贯通 | 小范围安装探针后，立即建立可运行的产品入口、一个员工/连接/Skill、真实业务工具、统一计算和通用结果；同步落实基础身份、凭据、外发、取消与已完成历史。 | AC-01、AC-02，以及 AC-10、AC-11、AC-12 的本增量实际使用路径。真实来源缺失时只能报告受控部分完成。 |
| I2 连续性与控制 | 同一业务链上增加必要待办、补充继续、确认信息管理、最小绑定测试禁用入口，以及产品记录和原生历史的基础备份恢复。 | AC-03、AC-04、AC-06、AC-07、AC-10、AC-12；重新驱动受影响的 J1/J2/J3。 |

薄探针只验证当前真实工作所使用的装配、工具、Client、Session、实际派发与存储接口。其首个代码成果必须是可启动入口及原生业务工具/展示路径，而非只有 schema、文档、扫描器或通用夹具平台。

允许在新工程内调整产品插件、业务插件、测试、必要小接口和局部目录组织；不得因此重新引入旧 Runtime/SDK 或更换已选底座。新工程的具体文件映射在 I1 的代码与说明中明确，不把尚不存在的目录或 API 当成已检查的源码事实。

若明确请求完整实施本合同，I1/I2/I3 是施工顺序，不是每完成内部增量都重新请求一次授权；真实权限、外部系统修改、目标变更等独立边界仍需处理。只授权某增量时不擅自扩大。
