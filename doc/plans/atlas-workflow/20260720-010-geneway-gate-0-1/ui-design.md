# geneway 界面设计说明

状态：支持性 UI ADR（`ADR-UI-001` 已锁定；范围与验收权威以 `implementation-contract.final.md` 为准）

目标：让制造业员工只面对一个通用数字员工“小纬”，同时能处理主动出现的设备、产能、质量和交付异常，并看得懂专家团、Workflow、审批、数据来源和结果。

## 1. 设计原则

1. 始终只显示一个“小纬”通用数字员工，后台专家 Agent 不成为独立聊天成员；用户仍可指定专家或专家团。
2. 对话只是入口，异常待办、Workflow、任务、审批、证据和报告必须是结构化界面。
3. 展示正式步骤和结论，不展示模型内部思维链。
4. 任何等待都要说明原因：等待数据、等待审批、排队或系统故障。
5. 敏感数据在发送前按用户和会话受众过滤。
6. 设备告警、停机、产能落后等事实由确定性规则识别；小纬负责解释、组织专家和建议处理，不负责凭空判定异常。
7. 普通员工界面尽量简单；Capability、模型、Connector 和策略配置只放内部管理端。

## 2. 交互参考

| 参考 | 借鉴内容 | 不照搬内容 |
| --- | --- | --- |
| Codex 桌面应用 | 左侧工作入口、中间对话与执行时间线、右侧上下文检查器、底部 Composer | 不复制私有视觉、代码/终端术语或开发工具信息架构 |

| [TanStack Table](https://tanstack.com/table/latest/docs/installation) | 异常、任务、Evidence 和工单的轻量 headless 表格逻辑 | 不在浏览器保存业务权威或做越权宽表过滤 |
| ChatGPT / Claude | 简洁会话、附件、流式回答、继续追问 | 品牌视觉、黑盒式长任务体验 |

| [CopilotKit](https://github.com/CopilotKit/CopilotKit) | 仅参考生成式 UI 和 HITL 交互 | 不进入 MVP 依赖，不引入其会话/共享状态模型 |
| OpenHands / DeerFlow | 内部调试时查看步骤、工具结果和 Artifact | 不把开发者工作台作为客户页面 |
| GearJob | 制造业 ERP 对象、密集表格、工单和进度工作上下文 | 不复制 Frappe 页面和视觉样式 |
| Hive / Sharp Cell | 个别设备与现场交互参考 | UI 尚未正式对外定稿，不作为视觉基线 |
| [React Flow](https://reactflow.dev/) | Workflow 节点、连线、分支、缩放、运行状态和 Diff 的基础组件 | 不采用付费 Pro 模板，不把图形状态变成第二份 Workflow 权威 |

当前已经锁定实现底座、信息架构和交互线框，但具体高保真视觉仍要由真实组件原型决定，不以生成图作为实施 oracle。Gate 0.1 只交付一个真实小纬产品纵切；四个核心路由、异常中心和表格属于 Gate 0.2。Hive/Sharp Cell 不能代替任何设计门禁。

### 2.1 正式 UI 组合

```text
React + Vite
  ├─ Tailwind CSS 4            # geneway tokens、响应式和视觉 recipe
  ├─ Base UI                   # 无样式可访问组件
  ├─ assistant-ui              # 小纬 Thread / Composer / Tool / HITL
  │    └─ @assistant-ui/react-ag-ui
  └─ TanStack Table            # Gate 0.2 起用于轻量 headless 业务表格

AG-UI compatible adapter              # Control Plane/Runtime 事件 → UI projection
@xyflow/react                         # immutable WorkflowVersion → Workflow graph
```

`geneway` 自己拥有路由、应用壳、业务页、权限投影、任务状态、DOM 和 design token。Ant Design、Ant Design X、ProComponents、MUI、CopilotKit 和 Assistant Cloud 不进入 MVP 运行依赖。

assistant-ui 只负责对话交互行为和 AG-UI 事件解析。页面刷新先读取 Control Plane 快照，再按 event cursor 续传；`showThinking=false`，不展示原始 reasoning/思维链。Gate 0.1 禁用附件上传，只能选择服务端预置、脱敏、只读的 fixture；附件能力在 Gate 0.2 另行开放。

TanStack Table 从 Gate 0.2 起使用稳定版并由 lockfile 固定，不采用 beta。它只负责排序、筛选、分页、选择和展开。所有页面使用同一 `EnterpriseTable` wrapper；数据范围、服务端查询、字段权限和导出授权仍由 Control Plane/Connector Gateway 强制执行。

## 3. 信息架构

### 普通员工：Codex 式工作台

```text
左侧工作入口
├── 小纬
├── 异常与待办
├── 我的任务
├── Workflow
└── 历史会话

中间主工作区
├── 小纬对话与执行时间线
├── 异常列表与处理
├── 任务过程与报告
└── Workflow 图与审批

右侧上下文检查器
├── 当前任务或节点
├── Evidence 与 Lineage
├── 权限、数据范围和受众
└── Artifact 与恢复操作
```

1440px 以上显示左中右三栏；1280px 下右侧可收起；更窄屏幕使用 Drawer。右侧没有选中对象时隐藏，不永久占用空间。设备异常和产能落后同时出现在左侧计数、小纬异常卡和异常中心，不能只藏在表格里。

### 内部管理员

```text
平台管理
├── Capability
├── 数字员工
├── 专家与专家团
├── Connector
├── 模型路由
├── 权限策略
├── Eval
└── 审计与运行状态
```

普通员工不看到 Runtime、模型密钥、工具权限和 Connector 凭证。

## 4. 对话页

```text
┌──────────────┬──────────────────────────────────────┬────────────────────┐
│ 会话         │ 小纬                                 │ 当前任务           │
│              │                                      │                    │
│ ＋ 新建      │ 你好，我是小纬。                     │ 状态：等待确认     │
│              │                                      │ Capability         │
│ 今天         │ [用户上传：需求说明.docx]             │ 数据范围           │
│  客户方案    │ 我可以分析方案、进度和设备异常。      │ 已用时间 / 预算    │
│  生产日报    │ 我已组织专家团并生成流程图，请确认。  │                    │
│  异常待办 3  │ ┌──────────────────────────────────┐ │ 证据               │
│ 本周         │ │ 目标、步骤、参与专家、数据范围   │ │ 报告与附件         │
│  质量分析    │ │ [确认执行] [要求修改] [取消]      │ │                    │
│              │ └──────────────────────────────────┘ │                    │
├──────────────┴──────────────────────────────────────┴────────────────────┤
│ ＋附件 [小纬自动安排⌄]  输入问题……                    [发送]                │
└──────────────────────────────────────────────────────────────────────────┘
```

### 中间消息区

- 用户消息；
- 小纬回答；
- 文件卡；
- Workflow 确认卡；
- 任务进度卡；
- 审批卡；
- 结果摘要和报告卡；
- 错误与恢复卡。

当确定性规则发现紧急设备异常或产能落后时，小纬可以主动发送一张“运营异常卡”，但同一 `BusinessException` 只提醒一次；后续状态变化更新原卡或进入异常中心，不连续刷屏。卡片必须显示严重度、影响对象、检测时间、证据更新时间和“让小纬分析”入口。

### 右侧任务抽屉

- 当前状态和下一步；
- Capability 与版本；
- 数据范围、动作上限和会话受众；
- 步骤时间线；
- Claim、Evidence 和 Lineage；
- Artifact 下载；
- 成本、耗时和审计编号。

小屏幕中右侧抽屉改为底部全屏面板，不把三栏强行压缩。

小纬是唯一发言者。专家团只在任务卡中显示“设备专家已完成”“生产专家正在分析”等状态；最终回答、追问和责任归口都由小纬完成。

### 专家与专家团选择

输入框旁提供一个轻量选择器：

```text
[小纬自动安排]
[生产专家]
[设备专家]
[质量专家]
[方案专家]
[生产 + 质量专家团]
[更多…]
```

用户也可以直接输入“让设备专家分析”或“请生产和质量专家一起看”。小纬解析后必须在发送前或任务卡中回显：

```text
本次由：生产专家 + 质量专家
[修改专家] [继续]
```

交互约束：

- “小纬自动安排”是默认项，只调用完成任务所需的最小专家集合；
- 选择器只显示当前 Capability 允许且当前环境可用的专家/专家团；
- 无权限、未登记或不可用的专家不能选中，系统说明原因并给出替代项；
- 用户选择不会扩大数据范围、工具权限或动作等级；
- 指定专家后，聊天气泡头像和发送者仍是小纬；所选专家只出现在任务卡、Workflow 节点和结论来源中；
- 精确选择进入 Workflow/审批 hash，执行中不能静默换人。

## 5. 异常与待办中心

这不是聊天历史，而是持续刷新的制造运营工作面：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 异常与待办  [全部 18] [紧急 3] [设备 6] [产能 4] [质量 3] [交付 2] │
├──────────────────────────────────────────────────────────────────────┤
│ 🔴 CNC-017 连续停机 26 分钟                    影响 2 张工单         │
│    告警：主轴过载 / 未确认     负责人：未分配   14:32               │
│    [让小纬分析] [认领] [查看设备与工单] [标记已知]                  │
├──────────────────────────────────────────────────────────────────────┤
│ 🟠 WO-2026-0082 产能进度落后 18%               预计延期 5.5 小时     │
│    瓶颈：车床工序 / WS-LATHE-02   交付：明日 16:00                  │
│    [分析原因] [生成追赶方案] [查看 Workflow] [持续监控]             │
└──────────────────────────────────────────────────────────────────────┘
```

### 异常来源

- GearJob `MES Alarm Log`：严重告警、未确认告警；
- 设备状态和 `MES Downtime Summary`：停机、离线、持续时间；
- `Work Order`、`Job Card`：计划数量、实际数量、当前工序和完成进度；
- `MES Schedule` / `MES Schedule Item`：`has_delays`、`is_delayed` 和延误原因；
- `MES Daily KPI` / `Quality Inspection`：OEE、开动率、合格率和质量异常。

### 异常状态

```text
新发现 → 已确认 → 分析中 → 已给出方案 → 处理中 → 监控中 → 已解决
                                          └────────────→ 已忽略（需原因）
```

第一版“认领、标记已知、处理方案、监控”只改变 `geneway` 内部状态，不写回 GearJob。每条异常必须保存检测规则、阈值、原始对象、时间范围和 Evidence。

Gate 0.2 的异常动作必须按下表实现，不能用看起来可点击的按钮冒充真实能力：

| 动作 | Gate 0.2 行为 | 门禁 |
| --- | --- | --- |
| 查看详情、规则、Evidence | 真实可用 | 按 tenant/resource 鉴权，不泄露隐藏字段 |
| 认领、标记已知 | 真实可用，只改变 `geneway` 内部状态 | 服务端授权、审计、幂等和重复回调测试 |
| 让小纬分析 | 允许使用明确标识的模拟结果 | 页面和 Artifact 均标“模拟”，不得暗示已调用 GearJob 或真实专家 |
| 生成追赶方案、持续监控 | 禁用 | Gate D 真实 Connector 与 Capability 通过前不得开放 |

首页和小纬对话页顶部固定显示“待处理异常”摘要：紧急数、逾期数、当前负责范围和最近更新时间。它是异常中心的安全投影，不另建一份统计状态。

## 6. Workflow 可视化与确认

Workflow 不能只作为一段文字或聊天 Markdown 展示。React Flow 图是审批、执行和复盘的主视图；文字只作为辅助摘要。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 设备异常处理流程 v3    [与 v2 对比] [适用窗口] [成本 ¥3.2/¥10]      │
├──────────────────────────────────────────────────────┬───────────────┤
│ [告警进入] → [验证设备/时间] → [创建异常]             │ 节点详情      │
│                                  ├→ [设备专家] ─┐     │ 类型：Agent   │
│                                  ├→ [生产专家] ─┼→[小纬汇总]         │
│                                  └→ [质量专家] ─┘     │ 工具：只读    │
│                                              ↓       │ 数据：C2      │
│                                      ◇ 需要业务动作？ │ 超时：5 分钟  │
│                                      ├否→[持续监控]   │ 输出 schema   │
│                                      └是→[人工确认]   │ Evidence      │
├──────────────────────────────────────────────────────┴───────────────┤
│ 图例：○等待  ●运行中  ✓完成  !失败  ◆审批  ＋新增  －删除           │
│                          [确认此版本] [要求小纬修改] [取消]           │
└──────────────────────────────────────────────────────────────────────┘
```

图形要求：

- 节点类型至少包括开始、确定性处理、Agent、Tool/Connector、并行、条件、人工审批、验证、等待和结束；
- 点选节点能查看输入、输出 schema、Agent、工具、权限、数据等级、动作等级、预算、超时和重试；
- 运行时在同一张图显示等待、运行、完成、失败、阻塞和取消；
- `WorkflowVersion` 改动必须显示节点、边和参数 Diff；
- 图由不可变 DSL 生成，不能只保存在浏览器中；
- 图与 DSL hash 不一致时禁止审批；
- 普通员工可以让小纬修改流程，不直接编辑任意参数；内部管理员才有受控图形编辑权限。

Workflow 数据只允许单向流动：

```text
TS 固定对象模板 / Agent WorkflowDraft / 管理端表单
→ 同一种 WorkflowDraft JSON
→ Zod 4
→ Workflow Compiler
→ immutable canonical WorkflowVersion JSON + hash
→ React Flow
```

React Flow 不读取 TS 模板或 Agent 原始输出，不保存第二份节点/边权威，也不能把浏览器中的图反向当成已批准 Workflow。审批、运行图、时间线和版本 Diff 都绑定同一个 `WorkflowVersion.id + hash`。

分阶段界面边界：

| Gate | Workflow UI 行为 |
| --- | --- |
| Gate 0.1 | 展示固定模板经 Compiler 生成的只读节点图；可查看节点和批准准确 hash，不开放自由编辑 |
| Gate A | 展示 `solution.analysis.v1` 与单工单六节点固定流程；由普通 Worker Interpreter 执行 |
| Gate B | 图和审批体验不变，只增加排队、等待、恢复和多 Agent 子任务状态 |
| Gate C | 才显示 Agent 生成草稿、WorkflowPatch、condition/parallel/wait、图形 Diff 和重新审批 |

UI 组件可以从 Gate 0.1 起支持绘制条件、并行和等待节点，但 Gate C 前不得由用户或 Agent 创建这些动态节点；收到未开放 kind 时必须显示“当前门禁不支持”并禁止审批。

### 对话内确认卡

```text

│                                            │
│ 目标：分析客户 MES 建设需求                │

│                                            │
```

卡片必须显示：

- 要完成什么；
- 会用哪些 Agent 和工具；
- 会访问哪些数据；
- 最多允许做到什么动作；
- 预计步骤、时间和费用；
- 风险和审批有效期。
- 可点击的小型流程图和完整 Workflow 链接。

参数变化后旧卡片立即失效，用户必须确认新版本。

## 7. 长任务进度

默认只显示业务步骤：

```text
✓ 读取并分类资料
✓ 提取需求与约束
● 生成实施方案
○ 检查证据完整性
○ 生成人工复核稿
```

可展开“小纬的专家团进度”：

```text
需求分析员      已完成    发现 18 项需求、3 项冲突
方案架构师      进行中    正在生成系统边界和实施阶段
结果验证员      等待      等待方案初稿
```

这些名称表示本次任务调用的后台专家能力，不是新的聊天联系人。用户仍然只向小纬追问、纠正或确认。

不显示 token 级思维过程，只显示：

- Agent 身份和版本；
- 正式输入摘要；
- 正式输出摘要；
- 工具调用结果；
- Evidence；
- 错误、重试和人工反馈。

## 9. 工单进度卡（MVP 真实业务）

GearJob 第一版不展示完整 ERP 页面，只展示一个用户有权查看的 Work Order：

```text
┌────────────────────────────────────────────────────┐
```

边界状态必须有专门文案：无权限、工单不存在、计划数量为零、数据缺失、数据过旧和 GearJob 暂时不可用。不能让模型用推测值填满卡片。

## 10. 生产日报页面（MVP 后）

生产日报不是一大段聊天文字，而是结构化报告：

```text
日期与范围
├── 计划 / 实际 / 达成率
├── 工单延期
├── 停机与设备异常
├── 质量异常
├── 数据缺失与可信度
├── 风险与建议
└── 证据和数据更新时间
```

确定性指标使用表格和小型趋势图；Agent 解释放在指标旁。所有“可能”“推断”“建议”使用不同标签，不与事实混在一起。

## 11. 状态和反馈

统一状态：

```text
草稿 → 等待确认 → 排队 → 运行中 → 等待输入/审批
     → 已完成
     → 已取消
     → 失败，可恢复
     → 失败，需人工处理
```

每种状态都需要：

- 一句通俗说明；
- 用户当前能做什么；
- 是否会继续计费；
- 下一次自动重试时间（如有）；
- 审计编号。

四个核心路由与 `EnterpriseTable` 还必须实现统一页面状态矩阵：

| 状态 | 必须显示 | 允许动作 | 禁止 |
| --- | --- | --- | --- |
| initial loading | 页面骨架和当前范围 | 取消或返回 | 显示旧租户缓存数据 |
| empty | 为什么为空、如何开始 | 新建任务或调整范围 | 用错误态替代空态 |
| filtered empty | 当前筛选条件 | 清除筛选 | 暗示用户没有权限 |
| 403 forbidden | 通俗权限说明和审计编号 | 返回、申请权限 | 暴露资源名称、数量、字段或存在性 |
| 404 not found | 对当前用户不可见或不存在 | 返回列表 | 区分“存在但无权” |
| 409 / stale approval | 版本已变化及变化摘要 | 重新加载、重新审批 | 继续使用旧 hash |
| 5xx / offline | 服务暂不可用、是否已安全重试 | 重试、稍后继续 | 把未知状态显示为成功 |
| stale data | 数据时间和过期原因 | 刷新、查看证据 | 省略新鲜度警告 |
| recoverable failure | 失败步骤、影响和恢复点 | 补充信息、重试、取消、转人工 | 只显示技术错误码 |

## 12. 视觉方向

- 以 Tailwind CSS variables 和 Base UI wrappers 为底层，视觉参考 Codex 的内容优先、克制层级和按需展开，不复制其私有样式。
- 企业软件风格，浅色为默认，支持深色但不作为 MVP 门禁。
- 品牌主色 `#155EEF`，主文字 `#172033`，页面底色 `#F4F6F8`，容器底色 `#FFFFFF`；成功 `#168A5B`、警告 `#C77700`、错误 `#C9362B`。
- 默认圆角 8，使用细边框和弱阴影；禁止玻璃拟态、霓虹、大面积渐变和装饰性 3D。
- 字体优先 Inter、`PingFang SC`、`Microsoft YaHei`、`Noto Sans CJK SC`、sans-serif。
- 使用清晰的状态色，但不能只靠颜色表达成功、风险和错误。
- 正文优先可读性，报告和表格密度高于普通聊天，但保留足够间距。
- 工厂、车间、产线、日期和数据等级始终放在明显位置，减少“看错范围”。
- 附件、审批、Evidence 和 Artifact 使用稳定的卡片组件，不把结构化数据塞进 Markdown 表格。
- 异常与待办中心允许较高信息密度，但必须优先突出严重度、影响范围、负责人、时间和下一步。
- Workflow 默认展示业务节点；重试、outbox、checkpoint 等技术子步骤按需展开，避免普通员工看到基础设施噪音。
- `packages/design-system` 导出单一 `genewayTheme`、Base UI wrappers、业务组件 recipe、TanStack Table DOM recipe 和 React Flow CSS variables；不允许页面各自重定义一套颜色、圆角和密度。
- Hive/Sharp Cell 当前 UI 仅作弱参考，不复制未经确认的 token。
- 每个核心页面只有一个主任务：小纬对话、异常处理、Workflow 审批、任务证据分页展示，不再合并成一个超载 Dashboard。
- Gate 0/A 不显示业务表格导出入口。首次开放导出时，由服务端按当前 tenant、resource scope、field mask、filter 和 sort 重新生成并在下载前再次鉴权；前端不得导出缓存 rows。跨租户、禁字段、权限撤销和筛选后行列一致性必须有负面测试。

## 13. 分门禁界面验收

所有验收必须使用真实 HTTP 服务和真实浏览器；不能把 Gate 0、A、B、C 的能力合称“第一版”。

### Gate 0.1：安全产品纵切

1. Base UI、assistant-ui 和 React Flow 必须共用同一 `genewayTheme`；Ant Design、Ant Design X、ProComponents、MUI、CopilotKit、TanStack Table 和 Assistant Cloud 不在 Gate 0.1 lockfile；
2. 真实 Vite HTTP 应用交付 Codex 式应用壳和一个小纬方案分析路由；Workflow 审批、运行进度、结果和 Evidence 可在该任务上下文中展开，不要求四路由；
3. 所有对话只显示小纬，不出现可直接聊天的专家 Agent 身份；
4. 新建对话，分别验证“小纬自动安排”、指定一个专家和指定一个专家团；自然语言点名与选择器结果一致；
5. 从服务端清单选择预置、脱敏、只读的 fixture 发起 `solution.analysis.v1`；不出现任意上传、附件下载或 Artifact 存储入口；
6. TS 固定模板经 Compiler 生成 WorkflowVersion，React Flow 只读节点图显示同一 `id + hash`；
7. 点开节点查看输入输出、专家、工具、权限、预算和 Evidence；
8. 查看服务端 fake Runtime 结论与内联 Evidence，刷新后恢复同一状态；fake、fixture、simulation 标签在任务、步骤、结果和证据处持续可见；
9. SSE 断线重连不重复消息；
10. Playwright 在 1440×900、1280×800 和 768×1024 验证键盘导航和状态非颜色唯一表达；1440px 验证三栏，1280px 验证检查器收起，768px 验证左右区域改为 Drawer、focus trap/关闭后焦点恢复、Composer 可用、Workflow 可平移缩放；
11. assistant-ui 刷新、SSE 断线和乱序事件后从 Control Plane 快照/游标恢复；
12. Playwright 断言消息作者集合始终只有 `{user, xiaowei}`；专家名只允许出现在路由摘要、Workflow 节点、进度和 Evidence 归因中，不出现专家头像、独立 Composer、DM 或聊天链接；
13. 成功路径不允许用 `page.setContent` 或 route interception `fulfill` 主 HTML、JS/CSS bundle、Control Plane API；页面 task id 必须与 API、Postgres 事件、WorkflowVersion/hash、ApprovalVersion 和 SSE cursor 对得上；
14. 原始视觉证据写入 `/tmp/geneway-runs/<run-id>/ui/`；Git 只保存视觉结论和 evidence index，不提交整套原始截图。

### Gate 0.2：完整产品骨架

1. 增加异常与待办、Workflow、任务与证据路由，形成四路由状态矩阵；
2. 引入 TanStack Table 和统一 `EnterpriseTable`，验证服务端筛选、排序、分页和权限；
3. 开放受控上传、Artifact/VersityGW、报告下载和完整 Lineage；
4. 异常中心展示设备停机和产能落后 fixture、详情、规则、Evidence 和去重状态；真实分析仍必须明确标记模拟或暂不可用；
5. 四个路由覆盖 empty、403、5xx 后重试恢复和 SSE replay，并执行独立视觉回归。

### Gate A：真实 MVP

1. `solution.analysis.v1` 在相同固定图中切换到真实 OpenAI Runtime，不改变 WorkflowVersion wire contract；
2. 使用 `production.work-order-status.v1` 查询一个 GearJob 工单，看到六节点流程、状态、计划/已产数量、确定性进度、更新时间和 Evidence；
3. 自动、单专家和专家团路由都能回显实际版本，最终仍由小纬回复；
4. Gate A 不显示 Agent 动态生成、condition/parallel/wait 或自由图编辑入口。

### Gate B：可靠长任务

1. 同一 Workflow 图增加排队、等待、恢复和多 Agent 子任务状态，不改变审批 hash；
2. Runtime/Interpreter/Hatchet 重启后从安全 checkpoint 继续，界面不重复完成步骤或消息；
3. 用户可以补充输入、取消或转人工，等待时不误显示为仍在计费执行。

### Gate C：动态 Workflow

1. Agent 只能提交结构化 WorkflowDraft/WorkflowPatch，界面不接受 TS 或脚本；
2. condition、parallel、wait 节点可视，Compiler 失败时显示可行动的原因；
3. 修改节点、边或参数后显示图形 Diff，旧审批立即失效；
4. 用户批准准确 canonical WorkflowVersion hash 后才能运行。

所有 Gate 都必须验证：低权限用户不能从专家选择、URL、会话历史、工单卡、异常详情、Workflow 节点或 Artifact 下载链接读取越权内容。

若 assistant-ui 或 Base UI 的某个组件限制业务任务、证据或权限体验，只替换该原子组件，保留 `genewayTheme`、AG-UI compatible event contract、Control Plane 权威和 Codex 式工作台结构。
